Tool Focus / Codex

把自然语言变成可运行的代码

Codex 是 OpenAI 推出的云端代码智能体。它不仅能写代码，还能在隔离环境中运行、调试、读取文件并返回结果。本指南面向需要用脚本处理数据、自动化报表或快速验证想法的同事。

01 / 它是什么

从“代码补全”到“端到端代码任务”

Codex 经历了三代明显变化。今天的版本已经不是一个简单的代码编辑器插件，而是一个能独立完成小型工程任务的云端智能体。

代码补全模型

根据上下文预测下一行代码，主要解决“怎么写”的问题，仍需人工运行和调试。

对话式编程助手

可以解释代码、生成片段、回答技术问题，但代码仍在本地编辑器里，执行环境由用户自己维护。

云端代码智能体

理解任务目标后，自动规划、写代码、在沙箱中运行、读取输出、修复错误，并交付可下载结果。

02 / 与 WorkBuddy 的区别

不是替代，而是互补

WorkBuddy 更擅长围绕本地工作空间和业务连接器完成办公任务；Codex 更擅长在云端沙箱里写代码、跑数据和验证算法。两者可以组合使用。

维度WorkBuddyCodex
主要入口桌面客户端，围绕本地工作空间网页或 API，围绕云端沙箱
最擅长文档处理、飞书协同、PPT/Excel 生成代码编写、数据分析、脚本自动化
执行环境本地电脑 + 已授权连接器OpenAI 云端隔离沙箱
结果形态.xlsx / .pptx / 飞书文档 / 邮件.py / .csv / 图表 / 运行日志
典型用户设计、经营、管理、综合岗位数据、开发、技术管理岗位
组合用法用 WorkBuddy 整理业务需求与原始数据 → 让 Codex 生成并运行分析脚本 → 结果回 WorkBuddy 生成汇报材料

提示：在窄屏设备上可以左右滑动查看完整表格。

选型建议：如果任务主要是“读本地文件、生成 Office 材料、发送到飞书”，优先用 WorkBuddy；如果任务需要“写代码、做数据清洗、跑统计模型、验证算法”，优先用 Codex。
03 / 典型场景

这些工作适合先交给 Codex

选择任务时，优先挑“输入清楚、输出可验证、错误可接受”的数据或代码任务。

场景 01：把多份 Excel 合并成一张干净的表

常见于经营、财务、项目管理：不同部门发来的表格字段名不同、日期格式混乱、有空行空列。Codex 可以写一个 Python 脚本，统一格式后输出一张主表。

3-5 个来源文件
1 个标准化输出
可重复脚本可复用

场景 02：按规则自动生成周报数据摘要

读取本周任务工时 CSV，按项目汇总人天、计算完成率、识别逾期任务，输出一段 Markdown 摘要和一张汇总表。

原始数据任务工时表
运算汇总 + 逾期识别
输出Markdown + CSV

场景 03：快速验证一个 API 接口

给 Codex 一份接口文档和测试账号（注意脱敏），让它生成请求脚本、打印响应字段、检查状态码，并把结果整理成表格。

输入接口文档
执行请求 + 解析
输出测试报告

场景 04：从原始数据生成可复用的分析图表

上传原始数据，要求 Codex 做描述性统计、画趋势图或分布图，并把图表和分析结论打包成 HTML/PDF 报告。

数据原始表格
分析统计 + 可视化
交付图表 + 结论
04 / 使用流程

四步完成第一个 Codex 任务

不要把整个项目一次性丢给 Codex。先定义清楚输入、输出和验收标准，再逐步扩大任务范围。

01准备输入把数据、字段说明、期望输出格式整理到一个文件夹或一段描述里。
02描述任务用“角色 + 目标 + 输入 + 输出 + 约束”五段式写提示词。
03运行与观察看 Codex 如何规划、写代码、运行。遇到报错先让它自己解释并修复。
04下载并验证把结果拿回本地，用原始数据抽样核对，确认无误后再用于正式场景。

安全边界提示

Codex 的云端沙箱会在任务结束后销毁，但上传的文件内容仍可能被记录用于模型改进（视 OpenAI 当前策略而定）。因此：不要上传合同金额、个人信息、密码、Token、内部代码仓库。

05 / 提示词模板

三段式提示词，让代码更可控

好的 Codex 提示词和给 WorkBuddy 的提示词结构类似：先交代背景，再明确任务，最后给出验收标准。下面给出三个可直接复用的模板。

模板 A：数据清洗与合并

你是一名数据工程师。当前任务是将多个格式相近的 Excel/CSV 文件合并成一张标准表。 输入： - 文件位于 /data 目录，扩展名为 .xlsx 和 .csv； - 每个文件都有“项目名称、日期、金额、负责人”四列，但列名可能不完全一致； - 日期格式可能是 2024/1/15、2024-01-15 或 15/01/2024。 目标： 1. 读取所有文件； 2. 把列名统一为：project_name, date, amount, owner； 3. 把日期统一为 yyyy-mm-dd； 4. 删除完全空行； 5. 输出 merged_cleaned.csv 到 /output，并打印行数、金额总和、最早/最晚日期。 约束： - 遇到无法解析的日期，保留原值并单独输出到 /output/parse_errors.csv； - 不要修改原始文件； - 执行前先向我确认你的字段映射方案。

模板 B：生成统计摘要

你是一名数据分析助手。请分析 /data/task_hours.csv，生成本周工作摘要。 字段说明： - project：项目名称； - name：成员姓名； - task：任务名称； - planned_hours：计划工时； - actual_hours：实际工时； - status：状态，值为 已完成 / 进行中 / 未开始； - due_date：截止日期（yyyy-mm-dd）。 任务： 1. 计算每个项目的总计划工时、总实际工时、完成率； 2. 找出实际工时超出计划 20% 以上的任务； 3. 找出已逾期且状态不是“已完成”的任务； 4. 输出 summary.csv 和一段 Markdown 摘要，包含关键数字和行动建议。 验收标准： - 所有数字必须能在原始表中逐条追溯； - 输出文件保存到 /output； - 摘要不超过 300 字。

模板 C：接口测试脚本

你是一名后端测试工程师。请根据下面的接口描述生成 Python 测试脚本，并在沙箱中运行。 接口：GET https://httpbin.org/get 要求： 1. 发送 3 次请求，每次带不同参数 name=alice/bob/carol； 2. 检查响应状态码是否为 200； 3. 提取响应中的 args.name 和 origin 字段； 4. 把结果输出到 /output/api_test.csv，列：request_no, name, origin, status； 5. 打印通过/失败总数。 注意： - 不要上传任何真实内部接口地址或凭据； - 若网络不通，输出错误日志并说明原因。
06 / 验收清单

代码任务完成不等于业务可用

Codex 生成的代码可能看起来正确，但运行结果仍需人工核验。以下清单帮助你在正式使用前完成必要检查。

可以继续扩大使用的信号

  • 脚本运行无报错，输出格式稳定
  • 抽样核对结果一致
  • 异常数据有单独日志
  • 任务描述可以复用到类似数据

需要暂停并人工介入的信号

  • 关键数字与原始表对不上
  • 静默丢弃了空值或异常行
  • 输出文件无法打开或乱码
  • 上传了敏感或授权信息
下一步：找一份非敏感的、结构清晰的表格数据，用模板 A 或 B 完成第一个任务；也可以先看AI 工具升级地图，理解 Codex 在整个工具生态中的位置。
