Contribute after success

这件事已经跑通了吗？

先完成任务并检查结果，再让 WorkBuddy 从当前对话中整理方法。你不需要另写一篇教程，只需要检查脱敏预览、选择发布范围并明确确认。

开始条件 有输入，有结果，也知道怎样判断结果可用

如果任务仍在试错、结果无法复现，先回到学习中心继续完善。

Before / 开始之前

先判断现在是否适合贡献

贡献的是可复现的方法，不是未经确认的聊天记录。

先不要发布结果还没有打开检查

仍有明显错误，或还说不清输入、输出和适用限制。

可以开始同类任务已经成功完成

关键步骤清楚，结果可检查，也知道哪些判断必须由人完成。

Flow / 四步完成

把整理工作交给 WorkBuddy

发布前始终由你掌握内容和范围。

01复制指令在刚刚完成任务的同一对话中发送。
02生成预览Agent 提取步骤、提示词、产物和验收标准，并完成脱敏。
03选择范围由 Agent 询问个人、部门或组织范围，不替你决定。
04确认发布检查标题、类型、脱敏结果和范围后，再明确同意。
Agent instruction / 直接使用

把下面这段话交给 WorkBuddy

建议在原任务对话中发送，Agent 才能读取完整上下文。

我刚刚完成了一个已经确认有效的任务。请读取当前对话、输入文件结构和输出成果，并读取当前工作空间中的 workbuddy-hub/agent-skill/SKILL.md。 请自动提取任务目标、输入要求、处理步骤、成功提示词、输出契约、验收标准和人工复核点；扫描并替换个人信息、真实项目名、绝对路径、凭据和业务敏感数据。 先生成脱敏后的发布预览，不要直接发布。预览完成后询问我选择个人、部门或组织范围；只有我明确确认标题、类型、脱敏结果和范围后才发布。
没有读取到指导文件？把 workbuddy-hub/agent-skill/SKILL.md 加入当前工作空间，再让 WorkBuddy 重新读取。不要跳过脱敏预览和范围确认。
Scope / 发布范围

范围由你确认，不由 Agent 猜测

内容越接近真实业务，越应该从更小范围开始。

个人先留给自己复用

适合仍在迭代、包含个人工作习惯的方法。

部门供同类岗位共同改进

适合口径一致、已完成脱敏的团队方法。

组织作为通用案例开放

只发布无业务敏感信息、跨团队仍然适用的内容。

Agent 可以代你完成

  • 从当前任务提取可复现步骤
  • 生成案例或 Skill 包初稿
  • 扫描敏感信息并制作脱敏预览
  • 询问并记录你选择的范围

必须由你确认

  • 结果是否真的跑通并可验收
  • 业务口径与适用限制是否准确
  • 脱敏结果是否足够
  • 最终标题、类型与发布范围
WorkBuddy 贡献方法
