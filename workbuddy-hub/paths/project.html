Path 02 / Project

让项目周报先变成一张可行动的状态表

这条学习线只讨论项目推进：把多人、零散、口径不一的周报归拢为进度、风险、证据和下一步动作。AI 负责信息处理，人负责专业判断和协调决策。

适用对象设计人员、项目及专业负责人
练习用时15 分钟
目标成果项目状态表 + 协调清单
01 了解02 学习03 使用04 共享
项目风险必须能回到周报原文。AI 可以归拢和提示，不应凭“进行中”三个字替负责人判断延期。
01 / 了解

项目管理的难点不是“没有周报”，而是缺少同一张图

同一个项目可能散落在多人周报、飞书文档和基础台账里。真正有价值的输出不是一段漂亮摘要，而是把计划与实际对齐，把风险原句保留下来，再明确需要谁做什么。

INPUT碎片信息成员周报、项目基础信息、计划进度和报告周期。
WORKBUDDY对齐与提取按项目合并，提取进展、风险、阻塞、动作和原文证据。
HUMAN判断与协调确认真实进度、风险级别、责任对象和资源安排。
判断边界：“未收到审查意见，可能影响下周出图”可以作为风险证据；“本周持续推进”不能单独证明延期。无法确认的内容必须标为“待人工确认”。
02 / 学习

先把项目名称、计划口径和报告周期对齐

如果基础信息不一致，再强的模型也只会更快地产生一张错误的表。练习前先准备两份材料并确认四个问题。

飞书周报碎片样例.csv8 条脱敏周报记录，用于提取进展、风险和下周计划下载样例
项目基础信息.csv5 个项目，包含项目经理、计划进度和目标节点下载样例

开始前确认

  • 项目名称或别名能否正确匹配
  • 计划进度对应哪个报告周期
  • 同一项目多人记录如何合并
  • 哪些词只能提示风险、不能直接定级

飞书联动时确认

  • 当前账号只能读取已有权限内容
  • 周报字段是否分列或混在正文中
  • 首次只选一个小范围文档验证
  • 正式输出仍需项目负责人复核

从本地样例迁移到飞书

本地练习跑通后，再把“读取两个 CSV”改为“读取指定飞书文档或多维表格”。分析口径、输出字段和验收条件保持不变，先验证连接器能看到哪些数据。

03 / 使用

实战：8 条周报归拢为 5 个项目状态

先让 WorkBuddy 说明匹配和评级口径，再生成结果。不要把“做得快”放在“证据可复核”前面。

8 条成员周报碎片
5 个统一项目状态
2 个样例中明显滞后项目
01按项目合并统一项目名称和负责人，把多人记录与基础信息对齐。
02提取原文证据分别提取本周进展、风险、阻塞和下周动作，保留出处。
03对照计划把计划进度和估算实际进度放在同一行，计算滞后百分点。
04形成风险状态高、中、低评级必须引用原文；证据不足就标待确认。
05形成协调动作列出需要谁参与、何时推进、为什么需要协调。
请读取工作空间中的 `飞书周报碎片样例.csv` 和 `项目基础信息.csv`。目标：把碎片化周报整理成统一的项目状态看板。请先说明项目名称匹配方式、报告周期和风险评级依据，确认后再输出： 1. 项目名称、项目经理、计划进度、估算实际进度、本周进展、Top3 风险、下周关键动作； 2. 风险状态评级高/中/低，并逐条引用周报原文证据； 3. 实际进度低于计划进度 10 个百分点以上的滞后项目清单； 4. 需要跨部门或管理层协调的事项清单，并标明需要谁参与； 5. 不要仅根据“进行中”推断风险，无法确认的地方标为“待人工确认”。

结果必须能回答

  • 哪个项目落后了多少
  • 风险判断依据是哪句原文
  • 下一步由谁做什么
  • 什么信息仍然缺失

交付前人工复核

  • 项目与负责人映射是否正确
  • 实际进度是否只是模型估算
  • 高风险是否有足够证据
  • 协调事项是否适合正式发出
样例中江北、东站项目的实际进度分别落后计划 11 和 15 个百分点。这是用于检验分析链是否跑通的参考结果，不代表真实项目结论。
04 / 共享

把“项目周报归拢方法”交给 Agent 打包

共享的是可迁移的方法：输入字段、匹配规则、证据要求、输出结构和复核边界，不是某个真实项目的数据。

我刚刚完成了“项目周报风险归拢”任务。请先读取并严格遵循当前工作空间中的 `workbuddy-hub/agent-skill/SKILL.md`。请从当前对话、输入文件结构和输出成果中提取可复用方法，重点保留项目匹配、计划对照、原文证据、风险评级、协调动作和人工复核规则。请移除真实项目名、人员信息、绝对路径和业务数据，先生成发布预览，不要直接发布。然后询问我选择个人、部门或组织范围；只有我明确确认预览和范围后才发布。

适合打包为案例

  • 保留一次完整输入与脱敏输出
  • 适合第一次照着复现
  • 重点展示证据与复核方法

适合继续升级为 Skill

  • 字段和步骤已重复验证
  • 触发条件与失败处理明确
  • 可以被不同项目反复调用
