# 四个实战演练操作手册

> 这份手册用于培训现场跟做和课后复现。每个演练都按“目标 -> 输入 -> 核心步骤 -> 输出 -> 提示词 -> 验收”展开。

## 演练 A：经营合同分析

### 目标

从合同台账、回款流水和客户信用等级中，自动识别逾期、低回款率、信用风险等异常账款，生成分级预警清单和管理摘要。

### 输入材料

培训样例：

- `sample-data/经营合同与回款样例.xlsx`

真实工作中可替换为：

- 合同主表：合同号、客户、签约金额、签约日期、账期条款、合同状态。
- 回款流水表：合同号、回款日期、回款金额。
- 客户信用等级表：客户名称、信用等级、建议账期。

### 核心步骤

1. 数据清洗与标准化：统一合同编号、日期格式、金额格式，剔除作废合同。
2. 计算理论回款截止日：根据签约日期和账期天数生成应回款截止日。
3. 汇总实际回款：按合同号汇总已回款总额，计算最近回款日。
4. 生成风险指标：回款完成率、剩余应收、逾期天数、信用等级。
5. 设置预警规则：高危、中危、关注、正常。
6. 输出预警清单：合同号、客户、金额、逾期天数、剩余应收、预警等级、建议动作。

### 建议预警规则

| 等级 | 规则 |
| --- | --- |
| 红色高危 | 逾期超过 90 天，或回款率低于 30%。 |
| 黄色中危 | 逾期 31-90 天，或回款率 30%-60%。 |
| 蓝色关注 | 逾期 1-30 天，或回款率 60%-80%。 |
| 正常 | 无逾期且回款率不低于 80%。 |

### 首轮提示词

```text
请分析 sample-data/经营合同与回款样例.xlsx。

目标：从合同主表、回款流水和客户信用等级中生成异常账款预警清单。

请按以下步骤执行：
1. 识别每个工作表的字段含义，说明你采用的统计口径。
2. 按合同号汇总已回款金额和最近回款日。
3. 根据签约日期和账期天数计算应回款截止日。
4. 计算回款率、剩余应收、逾期天数。
5. 按规则生成预警等级：红色高危、黄色中危、蓝色关注、正常。
6. 输出 Excel：预警清单、部门汇总、客户风险汇总、管理摘要。

请先列出你理解的字段和计算口径，我确认后再生成最终文件。
```

### 追问升级

```text
请把红色高危和黄色中危合同单独列出来，并为每条记录给出建议动作：经营催收、项目负责人沟通、暂停后续工作、提交管理层协调。
```

```text
请把管理摘要改成适合部门例会汇报的 3 条结论，每条结论都要对应具体金额或合同。
```

### 输出物

- 异常账款预警清单。
- 部门回款率汇总。
- 客户风险汇总。
- 管理层摘要。

### 验收清单

- 合同金额、已回款、回款率是否正确。
- 逾期天数是否按报告日期计算。
- 预警等级是否符合规则。
- 建议动作是否具体到责任方向。

## 演练 B：项目状态汇总

### 目标

从飞书周报或本地周报记录中提取项目进展、风险、阻塞点和下周计划，归拢为统一的项目状态看板。

### 输入材料

培训样例：

- `sample-data/飞书周报碎片样例.csv`
- `sample-data/项目基础信息.csv`

真实工作中可替换为：

- 飞书多维表格周报。
- 飞书文档周报。
- 项目基础信息表。

### 核心步骤

1. 定义提取模板：项目、人员、本周进展、下周计划、风险问题、需协调事项。
2. 文本预处理：按项目合并多人周报，去除寒暄和无关描述。
3. 自动打标：识别延期、阻塞、资料缺失、人力不足、审批中等风险词。
4. 归拢状态矩阵：每个项目一行，包含进度、风险、阻塞点、下周关键动作。
5. 输出看板：项目风险等级、滞后清单、需管理层协调事项。

### 首轮提示词

```text
请读取 sample-data/飞书周报碎片样例.csv 和 sample-data/项目基础信息.csv。

目标：把碎片化周报整理成统一的项目状态看板。

请输出：
1. 项目状态汇总表：项目名称、项目经理、计划进度、估算实际进度、本周进展、Top3 风险、下周关键动作。
2. 风险状态评级：高、中、低，并说明评级依据。
3. 进度滞后项目清单：实际进度低于计划进度 10 个百分点以上。
4. 需要院/部门协调的事项清单。

请保留关键原文证据，方便人工复核。
```

### 飞书真实场景提示词

```text
请读取我有权限访问的飞书周报文档/多维表格，筛选本周记录。
按项目汇总每位成员填写的本周进展、下周计划和风险问题，
生成项目状态看板，并标出需要管理层协调的事项。
```

### 追问升级

```text
请把风险状态为“高”的项目单独提取出来，按紧急程度排序，并写出本周建议推进动作。
```

```text
请把这个状态看板改写成 5 分钟部门例会口头汇报稿。
```

### 输出物

- 项目状态看板。
- 进度滞后清单。
- 风险事项清单。
- 部门例会摘要。

### 验收清单

- 是否按项目合并了多人周报。
- 风险等级是否有原文证据。
- 下周动作是否具体。
- 是否能看出谁需要协调什么。

## 演练 C：人员工作量评估

### 目标

整合任务工时、填报工时和项目分配数据，生成团队成员产能热力图，识别过载、闲置和填报异常。

### 输入材料

培训样例：

- `sample-data/任务工时样例.csv`
- `sample-data/工时填报样例.csv`
- `sample-data/人员投入样例.csv`

真实工作中可替换为：

- 任务管理系统导出表。
- 工时填报系统表。
- 项目人员分配表。
- 产出物统计表。

### 核心步骤

1. 统一人员与时间维度：处理姓名别名，确定评估周期。
2. 计算任务负荷：按人汇总任务实际工时。
3. 汇总填报工时：按人按日期汇总填报数据。
4. 交叉验证偏差率：比较任务实际工时和填报工时。
5. 计算有效产能：剔除会议、培训等非项目投入。
6. 生成热力图矩阵：人员 × 日期，人员 × 项目。
7. 输出行动建议：过载调配、闲置承接、异常复核。

### 建议规则

| 类型 | 规则 |
| --- | --- |
| 过载 | 日均实际工时超过 10 小时，或项目投入比例超过 100%。 |
| 闲置 | 日均实际工时低于 4 小时，且任务完成数偏低。 |
| 填报异常 | 任务实际工时与填报工时偏差超过 30%。 |

### 首轮提示词

```text
请分析 sample-data/任务工时样例.csv、sample-data/工时填报样例.csv 和 sample-data/人员投入样例.csv。

目标：生成团队成员工作量评估和产能热力图。

请输出：
1. 每人任务实际工时、填报工时、偏差率。
2. 每人当前项目投入比例汇总。
3. 过载人员、可承接人员、填报异常人员清单。
4. 人员 × 日期热力图数据表。
5. 人员 × 项目投入矩阵。
6. 面向项目负责人的任务调整建议。

请先列出你采用的统计口径和异常阈值。
```

### 追问升级

```text
如果新增一个需要 2 名结构专业人员、每人 30% 投入的新项目，请根据当前负载推荐人选，并说明风险。
```

```text
请把人员负载结果改写成适合管理层看的摘要：只保留过载、闲置、异常填报和建议动作。
```

### 输出物

- 人员负载汇总。
- 工时偏差复核表。
- 人员 × 日期热力图数据。
- 人员 × 项目投入矩阵。
- 调配建议。

### 验收清单

- 姓名是否匹配一致。
- 工时口径是否清楚。
- 偏差率公式是否正确。
- 建议是否考虑专业和项目连续性。

## 演练 D：周报转汇报 PPT

### 目标

将 Markdown 周报或项目材料自动整理成结构清晰、可继续编辑的 PPT 大纲或原生幻灯片，减少复制粘贴和排版时间。

### 输入材料

培训样例：

- `sample-data/周报转PPT样例.md`

真实工作中可替换为：

- 部门周报 Markdown。
- 项目进展 Word。
- 会议纪要。
- 图表和图片素材。

### 核心步骤

1. 规范 Markdown 层级：一级标题做封面，二级标题做页面标题。
2. 拆分幻灯片逻辑：一页只讲一个结论，内容太多自动拆页。
3. 内容排版映射：列表转要点，表格转表格页，风险转清单页。
4. 生成 PPT 大纲：先确认结构，再生成文件。
5. 后期微调：统一标题风格、页码、项目名称、汇报对象。
6. 输出与验收：检查标题层级、列表长度、表格是否截断。

### 首轮提示词

```text
请读取 sample-data/周报转PPT样例.md。

目标：生成一份 6 页以内的部门例会汇报 PPT 大纲。

要求：
1. 面向隧桥院全体或部门负责人，语言要清楚直接。
2. 页面结构建议：封面、总体进展、重点项目、风险与协调事项、下周计划、需要决策的问题。
3. 每页标题要是结论句，不要只写“项目情况”。
4. 每页不超过 3 个要点。
5. 先输出 PPT 大纲，我确认后再生成 PPT 文件。
```

### 追问升级

```text
请把这份 PPT 大纲改成更适合 5 分钟口头汇报的版本，删掉重复内容，突出风险和需要协调的事项。
```

```text
请根据确认后的大纲生成可编辑 PPT，并保持简洁商务风格。
```

### 输出物

- PPT 大纲。
- 可编辑 PPT 文件。
- 演讲者备注或口头汇报稿。

### 验收清单

- 页数是否控制住。
- 标题是否表达结论。
- 是否保留了关键风险和动作。
- 是否适合现场口头汇报。

## 综合建议：把四个演练串成任务调度中心

四个项目不是孤立的。更好的部门实践是：

1. 每周从飞书或本地文件汇总项目状态。
2. 每月分析合同回款和经营风险。
3. 每两周检查人员负载和项目分配。
4. 每次例会前自动生成汇报材料。

成熟后可以沉淀为固定任务卡：

```text
每周五 16:00，请读取本周项目周报和人员投入表，
生成项目状态看板、人员负载清单和下周例会 PPT 大纲。
输出到指定目录，并列出需要人工复核的事项。
```

自动化前必须先做到：

- 数据来源稳定。
- 字段口径固定。
- 输出模板固定。
- 人工复核责任明确。
