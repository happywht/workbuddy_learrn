# Hub 本地只读容量基线

## 结论

2026-08-08 在隔离的单副本 Hub API + PostgreSQL Docker Compose 中，对统一目录接口执行 5,000 次只读查询，20 并发下 5,000 次全部成功，p95 为 98.833 ms，通过“错误率 0、p95 不高于 1,000 ms”的试点检查。

该结果只能作为本机回归基线和生产压测 Profile，不能据此承诺 99.5% 可用性、生产吞吐、最终 Pod resources、HPA 上限或用户规模。

## Profile

| 项目 | 值 |
|---|---:|
| 目标 | `GET /api/v1/artifacts?kind=case` |
| Hub | 单副本、UID 10001、Uvicorn 默认单进程 |
| 数据库 | 隔离 PostgreSQL 16 Compose，4 个种子案例 |
| 预热 | 100 次 |
| 计量请求 | 5,000 次 |
| 并发 | 20 |
| 单请求超时 | 5 秒 |
| 客户端 | Python 3.12.10 / Windows 11 Docker Desktop |

## 结果

| 指标 | 结果 |
|---|---:|
| 成功 / 错误 | 5,000 / 0 |
| HTTP 200 | 5,000 |
| 错误率 | 0% |
| 总耗时 | 17.199798 秒 |
| 吞吐 | 290.701 req/s |
| 最小延迟 | 20.863 ms |
| p50 | 66.219 ms |
| p95 | 98.833 ms |
| p99 | 148.435 ms |
| 最大延迟 | 214.617 ms |
| 响应总量 | 10,765,000 bytes |

负载结束后的单次容器快照为 86.38 MiB、CPU 0.28%；它不是负载期间峰值，因此不用于资源定容。

## 可复现命令

```powershell
python deploy/performance/hub_load_probe.py `
  'http://127.0.0.1:18170/api/v1/artifacts?kind=case' `
  --requests 5000 --concurrency 20 --warmup 100 `
  --max-error-rate 0 --max-p95-ms 1000
```

运行使用独立 Compose 项目 `workbuddy-hub-load-ci` 和端口 `18170/55500`；测试后容器、网络、volume 和 Hub 镜像均已清理，原 8100 服务未参与负载。

## 生产退出门

生产同构压测至少还需覆盖：

- 双副本、真实 Ingress/TLS/OIDC 和跨节点调度；
- PostgreSQL 连接池、慢查询、锁、故障转移和备份窗口；
- SkillHub 查询/下载、Matrix 长轮询/文件、OTLP 导出和上游超时；
- 典型并发、峰值持续时间、大包、取消、断线恢复及依赖降级；
- CPU/内存峰值、连接数、队列、5xx、p95/p99、重启恢复和单节点故障。

只有生产压测与试点流量完成后，才能冻结 SLO、requests/limits、HPA、容量余量及告警阈值。
