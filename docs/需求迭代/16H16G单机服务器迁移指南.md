# WorkBuddy 16H16G 单机服务器迁移指南

> 适用对象：个人开发者先在 Windows + Docker Desktop 验证，再迁移到一台 16 核 16 GB Linux 服务器。
> 当前固定版本：SkillHub `v0.2.16`、AgentTeams `v1.2.2`。

## 1. 现在不需要准备什么

本地阶段不需要 Kubernetes、OIDC、企业域名、告警负责人或正式 SLO/RPO/RTO。当前使用 `local-dev` 身份即可验证完整功能。只有准备让其他人从公网使用时，才需要服务器地址、域名和 HTTPS。

## 2. 服务器最低条件

- Ubuntu 22.04/24.04 x86_64；16H16G 可承载个人或小范围试用；
- 建议至少 100 GB SSD；Skill 包、Matrix 文件和数据库都会增长；
- Docker Engine + Compose v2、Git、curl；
- 防火墙初期只开放 SSH `22`、HTTP `80`、HTTPS `443`；数据库端口不对公网开放；
- 最好准备一个域名，例如 `workbuddy.example.com`。没有域名时可先用 SSH 隧道测试，不直接暴露管理端口。

## 3. 推荐单机布局

```text
/opt/workbuddy/app          WorkBuddy 仓库
/opt/workbuddy/skillhub     SkillHub 固定版本部署文件
/opt/workbuddy/agentteams   AgentTeams v1.2.2
/opt/workbuddy/backups      加密备份
```

三个系统保持独立容器、数据库和数据卷，通过 Docker 网络与 Hub 适配器连接。不要让三套系统共享数据库。

## 4. 迁移顺序

1. 安装 Docker，确认 `docker version` 和 `docker compose version` 正常。
2. 克隆本仓库到 `/opt/workbuddy/app`，创建 `deploy/compose-poc/.env`，所有密码随机生成，绝不提交 Git。
3. 部署 SkillHub `v0.2.16`，保留 PostgreSQL、Redis 和 Skill 存储 volume；Hub 内部地址指向 SkillHub API。
4. 部署 AgentTeams `v1.2.2`，选择 OpenAI-compatible，填写已有的模型 `BASE_URL`、`API_KEY` 和 `MODEL`；Base URL 只写一次，通常以 `/v1` 结尾。
5. 创建 `workbuddy-local` Team、`workbuddy-leader` Worker 和 Hub 专用 Matrix 账号/Token。
6. 启动 WorkBuddy Hub，运行数据库迁移，再执行 smoke。
7. 最后配置 Nginx/Caddy HTTPS，只把统一门户和必要的 AgentTeams/SkillHub 页面暴露给用户。

AgentTeams Linux 官方入口使用固定版本环境变量，执行已检出的安装脚本，不使用漂移的 `latest`：

```bash
export AGENTTEAMS_VERSION=v1.2.2
cd /opt/workbuddy/agentteams
bash install/agentteams-install.sh
```

安装时选择“手动 / OpenAI-compatible”，再输入模型三项。不要把 Key 写进 shell history；正式迁移时应放进权限为 `600` 的环境文件或 Secret 管理器。

## 5. 验收命令

在服务器本机执行：

```bash
curl -fsS http://127.0.0.1:8100/health
python3 /opt/workbuddy/app/deploy/compose-poc/smoke.py http://127.0.0.1:8100
docker ps --format 'table {{.Names}}\t{{.Status}}'
```

smoke 必须同时出现：

```json
{"skillhub":"connected","agentteams":"connected"}
```

随后在浏览器确认：

- `/skills/` 显示“SkillHub 已连接”；
- `/collaboration/` 显示“AgentTeams 已连接”且至少一个 Team 可投递；
- 创建真实协作任务后，Worker 回复中包含完整 Hub task ID；
- 页面没有“等待连接 Hub API”或“需要登录”。

## 6. 备份和恢复

个人试用建议每天备份一次，至少保留 7 天。Hub 已提供：

```bash
python3 deploy/compose-poc/backup.py --project workbuddy-hub-poc --env-file deploy/compose-poc/.env --output-dir /opt/workbuddy/backups
```

迁移完成当天必须运行一次 `restore_drill.py`。只有“成功恢复并通过 smoke”的备份才算可用备份。

## 7. 什么时候再考虑企业配置

- 两人以上长期使用：启用 OIDC 和按部门权限；
- 对外提供服务：固定域名、HTTPS、限流和登录；
- 需要承诺稳定性：再设 SLO 99.5%、RPO 24 小时、RTO 4 小时作为起点；
- 有专职运维后：接 Alertmanager/邮件/企业 IM，并明确告警负责人；
- 单机资源持续超过 70% 或出现高可用要求：再迁移 Kubernetes/多节点。

这些是后续升级条件，不是当前本地开发的前置材料。
